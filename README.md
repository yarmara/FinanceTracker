# Finance Tracker

**Finance Tracker** — локальное настольное приложение для Windows для личного финансового учёта, контроля текущих денег, обязательств, плановых расходов, ожидаемых поступлений и расчётов с клиентами.

Текущая описываемая версия: **v1.17**.

Приложение написано на **C# / .NET 8 WinForms** и использует локальную базу **SQLite**. Отдельный сервер базы данных не нужен. Финансовые данные хранятся локально на компьютере пользователя.

---

## 1. Основной принцип работы

Главная задача программы — после запуска сразу показать реальное финансовое положение и дать возможность быстро зарегистрировать новую операцию.

На Главной странице отображаются:

- фактический остаток денег;
- задолженность по открытым займам клиентов;
- обязательные и необязательные запланированные платежи;
- свободные средства после резервирования обязательств;
- ожидаемые поступления текущего месяца;
- ближайшие обязательства;
- ожидаемый доход;
- прогноз до конца текущего месяца;
- доход прошлого месяца.

Основные ежедневные действия доступны крупными кнопками:

- **+ Поступление**;
- **− Расход**;
- **↩ Возврат**;
- **⇄ Перевод**.

Приложение не пытается заменить полноценную бухгалтерскую или налоговую систему. Оно предназначено прежде всего для управленческого учёта фактических денег, планов и обязательств.

---

## 2. Денежные единицы

### В интерфейсе

Все суммы вводятся и показываются в **тысячах рублей**.

Примеры:

- `10,5` = **10 500 ₽**;
- `100` = **100 000 ₽**;
- `0,75` = **750 ₽**.

В зависимости от региональных настроек Windows десятичным разделителем может отображаться запятая.

### В базе данных

В SQLite деньги хранятся в **копейках целыми числами**, чтобы избежать накопления ошибок округления.

Изменение интерфейса на тысячи рублей не меняет единицы хранения существующей базы и не требует пересчёта старых данных.

---

## 3. Где хранятся данные

Основная база данных:

```text
%LOCALAPPDATA%\FinanceTracker\finance.db
```

Например:

```text
C:\Users\<пользователь>\AppData\Local\FinanceTracker\finance.db
```

Приложение не требует удалённого сервера и не отправляет финансовые данные в интернет.

При обновлении программы **не удаляйте папку `%LOCALAPPDATA%\FinanceTracker`**, если хотите сохранить существующие данные.

# 4. Главная страница

Заголовок приложения: **Finance Tracker**.

## 4.1. Семь основных расчётных карточек

На Главной расположены семь основных показателей.

### 1. Общий баланс

Фактический остаток денег на всех активных счетах с учётом:

- начальных остатков;
- поступлений;
- расходов;
- возвратов клиентам;
- переводов между счетами;
- корректировок.

Перевод между собственными счетами не меняет общий баланс: деньги только перемещаются с одного счёта на другой.

### 2. К возврату клиентам

Сумма всех ещё не погашенных обязательств по открытым займам клиентов.

Для каждого займа расчет такой: Рассчитано к возврату минус уже возвращено

### 3. Остаток обязательных платежей на текущий год

Сумма обязательных плановых расходов, которые в соответствии с правилами программы должны быть зарезервированы сейчас.

В показатель входят:

- **ежемесячные расходы** — только текущий месяц;
- **раз в квартал** — очередные платежи, относящиеся к текущему году;
- **раз в несколько месяцев** — очередные платежи, относящиеся к текущему году;
- **ежегодные расходы** — обязательство текущего года;
- **разовые расходы** — если их срок относится к текущему году;
- **просроченные разовые расходы прошлых лет** — пока они не оплачены.

Будущие ежемесячные расходы следующих месяцев текущего года заранее не резервируются.

### 4. Остаток обязательных платежей на текущий месяц

Непогашенные **обязательные** плановые расходы, срок которых приходится на текущий календарный месяц.

Частично оплаченный расход входит только своим оставшимся остатком.

### 5. Необязательные запланированные платежи на текущий год

Непогашенные плановые расходы текущего года, у которых **не установлен признак обязательного расхода**.

Этот показатель информационный. Он помогает видеть желательные будущие расходы, но **не уменьшает «Свободно по итогам»**.

### 6. Свободно по итогам

Основной показатель свободных денег:

Свободно по итогам =
Общий баланс
− К возврату клиентам
− Остаток обязательных платежей

Необязательные запланированные платежи в эту формулу не вычитаются.

### 7. Ожидаемое поступление в текущем месяце

Сумма ожидаемого **чистого** дохода по активным планам поступлений со сроком в текущем месяце.

Для обычного поступления учитывается оставшаяся ожидаемая сумма целиком.

Для планируемого займа учитывается сумма, которая останется после рассчитанного возврата клиенту.

Пример:

Ожидается поступление: 100
К возврату клиенту: 94
Ожидаемый чистый доход: 6

---

## 4.2. Наведение и клик по расчётным карточкам

Для семи основных карточек приняты два разных способа получения пояснений.

### Наведение мыши

Показывает **правило расчёта показателя** — то есть объясняет, что означает карточка и какие данные в неё включаются.

### Клик мыши

Под рядом карточек появляется серая область:

Состоит из:
...
...

В ней выводятся уже **конкретные текущие строки**, из которых сформирована сумма выбранной карточки.

Например:

- у Общего баланса — остатки по счетам;
- у К возврату клиентам — открытые займы;
- у обязательных платежей — конкретные платежи с датами и остатками;
- у ожидаемых поступлений — конкретные планы поступлений;
- у Свободно по итогам — счета со знаком `+` и вычитаемые обязательства со знаком `−`.

Повторный клик по той же карточке скрывает детализацию.

---

## 4.3. Ближайшие обязательства

Таблица предназначена для текущей работы, а не для полной истории.

Здесь показываются только **неисполненные** обязательства:

- возвраты клиентам;
- обязательные и необязательные плановые расходы, которые должны быть исполнены;
- просроченные и ещё не закрытые обязательства.

Полностью исполненные обязательства на Главной скрываются. Их можно посмотреть в соответствующей истории/операциях.

Обязательства текущего месяца выделяются визуально.

---

## 4.4. Ожидаемый доход

Таблица показывает активные ожидаемые поступления.

В ней отражаются, в частности:

- дата;
- источник/клиент;
- сколько ожидается получить;
- сколько уже поступило;
- сколько останется после возврата, если план связан с займом.

# 5. Прогноз на конец текущего месяца

Отдельный информационный блок расположен в одном ряду с таблицами **Ближайшие обязательства** и **Ожидаемый доход**.

Расчёт:

Общий баланс

- ожидаемый чистый доход со сроком до конца текущего месяца
  − возвраты клиентам со сроком до конца текущего месяца
  − обязательные плановые расходы со сроком до конца текущего месяца
  − необязательные плановые расходы со сроком до конца текущего месяца
  = Прогноз на конец текущего месяца

### Важные договорённости прогноза

1. Просроченные незакрытые суммы также учитываются, потому что их срок уже наступил.
2. Для ожидаемого займа используется **чистый результат после полного рассчитанного возврата**, даже если отдельная часть возврата по графику может приходиться уже на следующий месяц. Это сделано как более консервативный способ оценки ожидаемого дохода.
3. В прогноз вычитаются и необязательные расходы со сроком до конца месяца, хотя они не уменьшают показатель `Свободно по итогам`.

---

## 5.1. Доход прошлого месяца

Внизу блока прогноза показывается строка:

**Доход прошлого месяца**.

Он рассчитывается как:

1. фактические обычные поступления прошлого календарного месяца, которые **не создают обязательства возврата**;
2. плюс чистый результат займов, которые были **полностью закрыты именно в прошлом месяце**.

Для закрытого займа чистый результат:

Сумма поступления минус рассчитанная сумма к возврату

Займ включается в доход прошлого месяца по месяцу фактического полного закрытия возврата, а не обязательно по месяцу первоначального поступления.

# 6. Операции

Вкладка **Операции** содержит общий журнал фактического движения денег.

## 6.1. Виды операций

### + Поступление

Обычное поступление денег на выбранный счёт.

Можно выбрать:

- дату;
- счёт;
- клиента;
- категорию;
- связанный план поступления;
- сумму;
- комментарий.

Клиента разрешено выбирать и для обычного поступления **без обязательства возврата**. Это используется, например, когда клиент просто оплачивает услуги.

### Поступление с обязательством возврата клиенту

Если включён соответствующий признак, операция создаёт займ и обязательство возврата.

Такую операцию можно создать только для клиента с установленной галкой **Займы**.

### − Расход

Фактический расход с выбранного счёта.

Можно связать его с конкретным плановым расходом — тогда фактическая сумма уменьшит остаток соответствующего планового обязательства.

### ↩ Возврат

Фактический возврат денег по открытому займу клиента.

Операция привязывается к конкретному исходному поступлению/займу.

После сохранения возврата приложение сразу пересчитывает:

- К возврату клиентам;
- ближайшие обязательства;
- остатки счетов;
- статус займа;
- историю займа.

### ⇄ Перевод

Перевод между собственными счетами.

Он уменьшает один счёт и увеличивает другой на ту же сумму, не меняя общий баланс.

### Корректировка

Используется для ручного исправления остатка счёта, если фактический остаток необходимо привести в соответствие с реальностью.

---

## 6.2. Редактирование операций

Операции можно **изменять без удаления**.

Редактирование доступно кнопкой и двойным кликом по строке.

При открытии существующей записи должны восстанавливаться все сохранённые реквизиты, включая:

- дату;
- счёт;
- счёт назначения;
- клиента;
- категорию;
- план;
- сумму;
- комментарий;
- признаки займа;
- индивидуальный срок возврата.

Для связанных займов действуют проверки целостности. Например, нельзя убрать обязательство возврата у поступления, по которому уже существуют операции возврата, если это создаст противоречивые данные.

---

## 6.3. Фильтры операций

При открытии вкладки **Операции** по умолчанию показываются все операции **текущего календарного месяца** и все категории.

В начале строки фильтра находятся быстрые кнопки:

- **Прошлый месяц**;
- **Текущий месяц**.

После них находятся:

- дата `с`;
- дата `по`;
- категория;
- кнопка применения фильтра.

Фильтры даты и категории можно применять **одновременно**.

---

# 7. Клиенты

В справочнике клиентов хранятся обычные клиенты и клиенты, участвующие в возвратных операциях.

## 7.1. Галка «Займы»

По умолчанию у нового клиента галка **Займы** выключена.

Если она выключена:

- клиент считается обычным заказчиком услуг;
- его можно выбирать в поступлениях и планах поступлений;
- поля процента возврата и графика возврата скрываются;
- создать обязательство возврата для такого клиента нельзя.

Если галка включена:

- доступны процент возврата;
- доступен индивидуальный график возврата;
- клиент может использоваться в операциях займа.

---

## 7.2. Процент возврата

Принято универсальное правило:

Сумма к возврату = Поступление × (1 + процент / 100)

Примеры:

- `−5 %` → из 100 нужно вернуть 95;
- `0 %` → из 100 нужно вернуть 100;
- `+5 %` → из 100 нужно вернуть 105.

То есть отрицательный процент означает, что часть поступления остаётся как доход.

---

## 7.3. График возврата

Для клиента с займами можно задать несколько частей возврата.

Для каждой части задаются:

- процент общей суммы возврата;
- количество рабочих дней после поступления.

Сумма долей графика должна составлять **100 %**.

При создании займа условия графика фиксируются для конкретного поступления. Последующее изменение карточки клиента не должно изменять уже созданные обязательства по старому займу.

---

## 7.4. Рабочие дни

При расчёте сроков возврата автоматически исключаются:

- суббота;
- воскресенье;
- дополнительные нерабочие дни, заданные в Настройках.

---

## 7.5. Индивидуальный срок возврата в операции

В самой операции поступления можно указать **индивидуальный срок возврата именно для этой сделки**.

Он имеет более высокий приоритет, чем график, установленный в карточке клиента.

Если индивидуальный срок указан, для конкретного займа используется он.

---

# 8. История займов

Вкладка **История займов** предназначена не для всех операций, а именно для анализа поступлений с обязательством возврата и связанных с ними возвратов.

## 8.1. Режим по умолчанию

При открытии вкладки автоматически включается режим **Не закрытые**.

В нём показываются:

- полностью незакрытые займы;
- частично закрытые займы;
- независимо от даты первоначального поступления.

Это позволяет использовать вкладку как список текущих незавершённых расчётов.

## 8.2. Просмотр истории по периоду

Также доступны:

- **Прошлый месяц**;
- **Текущий месяц**;
- произвольный интервал дат;
- **Не закрытые** — возврат к списку текущих открытых займов.

## 8.3. Цветовые статусы

Строки выделяются тремя цветами:

- **зелёный — Закрыт**;
- **жёлтый — Частично**;
- **красный — Не закрыт**.

Легенда цветов находится в заголовке таблицы рядом с надписью **История займов**.

## 8.4. Информация по займу

В строке истории видно:

- дату исходного поступления;
- клиента;
- сумму поступления;
- сумму к возврату;
- сколько возвращено;
- остаток;
- счёт;
- категорию;
- расчёт по исходному поступлению;
- отдельный столбец **Операции возврата** с датами и суммами фактических возвратов;
- комментарий.

Статус займа рассчитывается по его **полному текущему состоянию**, даже если отдельные возвраты находятся за пределами выбранного для просмотра периода.

---

# 9. Счета

Можно вести несколько денежных счетов, например:

- наличные;
- банковские карты;
- расчётные счета;
- другие источники хранения денег.

Для счёта задаются:

- название;
- начальный остаток;
- активность;
- признак **Основной счёт для новых поступлений**;
- признак **Основной счёт для новых расходов**.

Основной счёт поступлений автоматически подставляется при создании новой операции поступления.

Основной счёт расходов автоматически подставляется при создании расхода и используется как удобное значение по умолчанию для исходящих операций.

Текущий остаток счёта рассчитывается автоматически по истории операций.

---

# 10. Категории

Справочник категорий находится на вкладке **Настройки**.

Категории не вводятся вручную заново в каждой операции, а выбираются из справочника.

Для категории задаётся область использования:

- **Поступления**;
- **Расходы**;
- **Поступления и расходы**.

Категории используются в:

- фактических поступлениях;
- фактических расходах;
- планах поступлений;
- планах расходов;
- фильтре журнала операций;
- истории и экспорте.

Для переводов между собственными счетами, возвратов и корректировок категория не является главным аналитическим признаком и может не использоваться.

Категории можно архивировать и возвращать из архива без удаления старой истории.

---

# 11. План расходов

План расходов хранит будущие обязательные и необязательные платежи.

Для расхода задаются:

- название;
- сумма;
- категория;
- периодичность;
- дата/день выполнения;
- признак **обязательный**;
- активность.

## 11.1. Периодичность

Поддерживаются:

### Ежемесячно

Задаётся день месяца.

В резерв Главной включается только текущий месяц, а не все будущие месяцы года.

### Раз в квартал

Задаётся дата первого платежа. Последующие платежи рассчитываются каждые 3 месяца.

### Раз в несколько месяцев

Задаются:

- дата первого платежа;
- интервал повторения в месяцах.

Допустимый интервал — от 1 до 120 месяцев.

### Ежегодно

Задаются день и месяц. Год исходной даты не используется как ограничение: обязательство повторяется ежегодно.

### Разово

Задаётся полная конкретная дата.

Разовый расход можно запланировать на будущий год.

### Договорённость по будущему году

Если в 2026 году создан разовый расход на 2027 год:

- он хранится в Плане расходов уже сейчас;
- в 2026 году не уменьшает свободные средства;
- не входит в платежи текущего года;
- не влияет на Главную как текущее обязательство;
- нужен как напоминание о будущем платеже;
- когда наступит 2027 год, он автоматически начнёт учитываться в расчётах 2027 года.

---

## 11.2. Обязательные и необязательные расходы

**Обязательные** расходы участвуют в резервировании свободных денег.

**Необязательные** расходы показываются отдельным информационным показателем и в прогнозе, но не уменьшают `Свободно по итогам`.

---

## 11.3. Частичная оплата

Если фактический расход связан с плановым платежом, программа учитывает уже оплаченную часть.

На Главной и в остатках показывается:

```text
Плановая сумма − уже оплачено
```

Полностью исполненные обязательства исчезают из списка ближайших обязательств.

---

# 12. План поступлений

Позволяет заранее записывать ожидаемые поступления.

Для плана можно задать:

- название;
- ожидаемую сумму;
- ожидаемую дату;
- клиента;
- категорию;
- комментарий;
- будет ли после поступления создано обязательство возврата клиенту.

Клиент может быть выбран и для обычного поступления без возврата — например, постоянный заказчик услуг.

Если включено обязательство возврата, клиент должен иметь признак **Займы**.

## 12.1. Частичное поступление

Фактические поступления могут частично закрывать план.

В программе сохраняются:

- плановая сумма;
- сколько уже поступило;
- сколько осталось ожидать.

---

# 13. Ближайшие обязательства и исполненные платежи

Главная показывает только то, что ещё требует действия.

Поэтому:

- полностью исполненные платежи скрываются;
- незакрытые просроченные остаются видимыми;
- завершённые факты сохраняются в операциях и истории.

Это сознательная договорённость: Главная — рабочий список, а не архив.

# 16. Резервное копирование базы

## 16.1. Ручной бекап

На вкладке **Настройки** есть кнопка создания резервной копии.

Архив создаётся **рядом с `FinanceTracker.exe`**.

Пример имени:

```text
FinanceTracker_backup_2026-10-07_10-15-30.zip
```

В архив помещается:

```text
finance.db
```

Перед копированием выполняется checkpoint SQLite.

После успешного создания нового архива старые архивы `FinanceTracker_backup_*.zip` удаляются. Таким образом рядом с программой хранится только **последняя успешная резервная копия**.

Сначала создаётся новый архив, затем удаляются старые — это уменьшает риск остаться без резервной копии при ошибке создания.

## 16.2. Автоматический бекап при запуске

В Настройках можно включить:

**Создавать ZIP-бекап базы при каждом запуске программы**.

Если опция включена, резервная копия создаётся при старте Finance Tracker.

---

## 16.3. Пароль на архив

В Настройках есть поле **Пароль на архив**.

### Если поле пустое

Создаётся обычный ZIP без пароля.

### Если пароль задан

Архив шифруется методом **AES-256**.

Для открытия такого ZIP рекомендуется использовать архиватор с поддержкой AES ZIP, например 7-Zip. Стандартный Проводник Windows может не поддерживать этот формат шифрования.

Сохранённый пароль в настройках дополнительно защищается через **Windows DPAPI для текущего пользователя**.

Практическое следствие: защищённое значение пароля привязано к учётной записи Windows. После переноса базы/настроек в другую учётную запись сохранённый пароль может потребоваться ввести заново.

# 18. Обновление и совместимость базы

В процессе разработки применяется принцип **добавочных миграций**:

- существующая `finance.db` остаётся на месте;
- новые столбцы и настройки добавляются автоматически;
- старые финансовые записи не пересоздаются;
- суммы не конвертируются заново;
- пользовательские операции не должны удаляться при обновлении программы.

Но перед установкой новой версии всё равно рекомендуется сделать резервную копию.

### Важно

При обновлении исходников/EXE заменяйте файлы программы, но **не удаляйте**:

%LOCALAPPDATA%\FinanceTracker\finance.db

```powershell
dotnet --version
```

Для текущего проекта ожидается версия ветки .NET 8, например:


## Сборка Release

В PowerShell:

```powershell
cd C:\FinanceTracker
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build-release.ps1
```

Готовый self-contained EXE:

```text
C:\FinanceTracker\publish\win-x64\FinanceTracker.exe
```

`-Scope Process` изменяет политику выполнения только для текущего окна PowerShell.

Self-contained сборка предназначена для запуска без отдельной установки .NET Runtime на целевом компьютере.

# 22. Рекомендуемый порядок первоначальной настройки

1. Открыть **Счета**.
2. Создать используемые счета и указать начальные остатки.
3. Отметить основной счёт для поступлений и основной счёт для расходов.
4. В **Настройки → Категории** создать нужные категории.
5. Создать клиентов.
6. Для обычных заказчиков оставить `Займы` выключенным.
7. Для возвратных клиентов включить `Займы`, задать процент и график.
8. Внести регулярные и разовые расходы в **План расходов**.
9. Внести известные будущие поступления в **План поступлений**.
10. При необходимости добавить праздники/нерабочие дни.
11. Настроить автоматический ZIP-бекап и при необходимости пароль.
12. После этого повседневную работу вести преимущественно через Главную и Операции.

# 23. Рекомендуемый порядок ежедневной работы

1. Открыть Finance Tracker.
2. Посмотреть:
   - Общий баланс;
   - К возврату клиентам;
   - обязательные платежи;
   - Свободно по итогам;
   - ближайшие обязательства;
   - ожидаемые поступления.
3. Вносить фактические поступления и расходы сразу после их совершения.
4. Возвраты клиентам проводить именно через операцию **Возврат**, связывая их с нужным займом.
5. Проверять **Историю займов** для незакрытых расчётов.
6. При необходимости анализировать операции текущего/прошлого месяца по категории.
7. Периодически создавать ручной бекап, даже если включён автоматический.

# 24. Что считается источником истины

- **Фактические деньги** — операции и рассчитанные остатки счетов.
- **Будущие расходы** — План расходов.
- **Будущие поступления** — План поступлений.
- **Задолженность перед клиентом** — конкретный займ и связанные операции возврата.
- **История** — сохранённые фактические операции; завершённые обязательства не удаляются только потому, что перестали показываться на Главной.

Эта договорённость позволяет разделять три разных понятия:

1. что уже реально произошло;
2. что запланировано;
3. что остаётся обязательством на текущий момент.
